# Changelog

## 6.0.0 — 12-10-26

- `feat(codex): add adaptive triage, skill eligibility, verification and trace`
- `refactor(codex)!: rename orchestration skill and agent presets`
- Added safe opt-in v5.0 migration with archived backups; preserved existing unrelated Skills and config.
- Included structural validators and opt-in minimal execution trace; hooks remain disabled.
- Existing optional plan schema remains `5.0` for compatibility. Use `scripts/migrate_plan.py` for old preset IDs; this is a separate plan schema version from the Kit release.


## 5.0.0 — 11-10-26

**`refactor(codex): generalize orchestration and reuse task-level skills`**

- Reused `$codex-universal-orchestrate` as the only orchestration Skill; replaced code-only planning with domain-neutral goal/deliverable/capability/risk planning.
- Replaced legacy `hy_*` agent choices with five `orch_*` presets: scout, analyst, executor, reviewer and expert; Terra remains optional A/B only.
- Changed *unnamed* subagent fallback to Sol Medium; Luna High is selected explicitly for bounded exploration.
- Added Skill-first discovery and executor-owned Skill activation and reporting, including no recursive orchestration in child threads.
- Added universal Task Contract, sample DAGs for research, engineering, mixed, deterministic cases and offline JSON validator.
- Added local Skill inventory helper, live evaluation plan and 12 pilot scenario labels.
- Preserved optional v4-compatible isolated worktree launcher; made report version 5 and disallowed API-key env fallback on explicit `--run`.
- Added installer dry-run and explicit, backup-first v4 upgrade; no silent deletion/overwrite of pre-existing Skills, policies or agents.
- Passed 35 offline unit tests. Real model routing/quality must be evaluated in a signed-in Codex Pro client.

### Breaking/intentional differences vs v4

- Old agent names `hy_*` are **not** the preferred v5 routing targets. Use `orch_*` after installation and inspect/deactivate old role presets explicitly.
- Plan JSON schema `5.0` is **new advisory validation format**, not a native Codex API and not directly compatible with the separate optional worktree launcher manifest schema `1`.
- `~/.codex/config.toml` is not overwritten; manual merge of different defaults may be needed. Existing users should run `--upgrade-v4` to replace known v4 Skill/policy after backup.
