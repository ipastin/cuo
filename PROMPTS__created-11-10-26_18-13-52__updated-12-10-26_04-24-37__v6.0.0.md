# Prompts for evaluating v5

## A. Skill discovery, read-only

```text
Используй $codex-universal-orchestrate. Не изменяй файлов и внешних ресурсов.
Сначала перечисли реально доступные Skills, релевантные для анализа текущего проекта.
Сделай компактный план, разграничь методы и Skills. Если ни один Skill не подходит,
не создавай новый. Выполни самостоятельный анализ в главном thread или делегируй
до двух независимых read-only подзадач при явной выгоде. Верни доказательства.
```

## B. Cross-domain product / research / engineering

```text
Используй $codex-universal-orchestrate. Проанализируй требования, собери проверенные
источники, предложи UX/продуктовое решение и implementation plan для текущей задачи.
Не создавай новые Skills или domain-orchestrators. Для каждой подзадачи подбери
существующие Skills и назначь исполняющему агенту точные имена. Запланируй
зависимости; независимые поисковые задачи можешь делегировать Luna, сложное
проектирование выполняй на Sol. Не меняй Figma и код без моей команды.
```

## C. Native subagents sanity check

```text
Используй $codex-universal-orchestrate. Проверь три разных аспекта документации
проекта двумя отдельными read-only агентами (если доступны) и дождись обоих.
Назначь required Skills только если они реально установлены. Итогом должна
быть таблица проверенных фактов с путями к источникам и список пробелов.
Не используй codex exec, worktrees или API.
```

## D. No-overengineering case

```text
Используй $codex-universal-orchestrate. Исправь одну конкретную опечатку в
указанном файле. Если работа прямолинейная, не создавай план, DAG и subagents.
Подтверди минимальный diff.
```

## v6.0 dry-run evaluation prompt

> Используй `$codex-universal-orchestrate`. Сначала оцени режим DIRECT / PLANNED / ORCHESTRATED и обоснуй решение. Проверь eligibility нужных существующих Skills в текущей Codex-сессии. Если нужно делегирование, передай точные Skill names каждому `cuo-*` исполнителю. Верни deliverables, проверяемые acceptance criteria и evidence, но не заявляй успех для непроверенных критериев. Не создавай worktrees, не меняй внешние сервисы и не запускай Hooks.
