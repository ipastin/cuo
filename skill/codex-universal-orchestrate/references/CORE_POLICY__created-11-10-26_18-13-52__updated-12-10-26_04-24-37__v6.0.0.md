# Universal Orchestration Core Policy

## Scope

Controls **how Codex works on tasks** in a logged-in ChatGPT Pro session. It does not manage model calls inside a user product and does not create a paid API gateway.

The same algorithm handles technical, creative, research, business, product, knowledge-work and cross-domain tasks. **Do not route by domain name alone.** A domain is context, not an orchestration runtime.

## Decision sequence

1. **Goal & deliverables:** identify observable outcome(s), constraints, source of truth and non-goals. Distinguish research from modification and decision from execution.
2. **Context:** inspect applicable AGENTS.md, accepted decisions, relevant files and tool permissions. Reuse available Skills and connected tools; don't fabricate access or metadata.
3. **Capability selection:** identify methods needed; look at installed skill names/descriptions, not the contents of every skill. Use existing Skills before inventing new ones. A missing Skill must be reported, not simulated.
4. **Task decomposition:** split by independently verifiable deliverable, actual dependency, and ability to isolate work. Never split merely to meet a target agent count.
5. **Plan:** create a DAG with task ID, evidence, `depends_on`, skills, executor, permission boundary, DoD, risk and ownership (only where relevant). No DAG for trivial requests.
6. **Route:** prefer deterministic tools for deterministic work, parent for short or coupled work, Luna for scoped search/extraction, Sol for synthesis/execution/review and Astra for consequential unresolved decisions. Agent role and Skill choice are separate.
7. **Execute in waves:** parallelize independent read-heavy tasks; keep coupled decisions and shared mutable artifacts sequential. Most tasks should use 0–2 subagents. Upper bound of 5 is a cap, not a quota.
8. **Verify:** evaluate deliverable-specific quality criteria. Check evidence, constraints, applicable tests, consistency, errors, safety and approvals. Report unverified items explicitly.
9. **Integrate:** main thread owns final synthesis, quality gates, file merge decisions and end-user report; do not replace objective checks with model self-assessments.

## Non-code tasks

No mandatory Git repository, `owned_paths`, code tests or worktrees. For research and strategy, use provenance, claims, source dates and decision quality. For UX, use flows, states, accessibility and handoff completeness *when requested*. For engineering, use runnable checks. For any kind of work, choose domain-appropriate acceptance criteria from existing Skills and project docs.

## Execution anti-patterns

- No separate orchestrator for every domain; no 'manager of managers' unless concrete constraints demand it.
- No automatic high-effort or Astra for keyword-triggered topics; use consequence and uncertainty.
- No Skill manager agent; the active executor selects and loads Skills.
- No creating Skill files to solve a one-time task.
- No auto-spawning worktrees or `codex exec` subprocesses from natural-language plans.
- No cloud API or undocumented provider fallback; use signed-in Codex models only.
