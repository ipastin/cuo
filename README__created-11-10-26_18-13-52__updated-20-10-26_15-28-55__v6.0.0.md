# Codex Universal Orchestration Kit v6.0.0

**Codex + ChatGPT Pro only.** No product LLM routing, API credentials, paid gateway, SaaS scheduler, or new domain-specific orchestrators.

## TL;DR

One main Sol Orchestrator can handle any work type. It reuses real existing Skills, designs an appropriately scoped plan, delegates to model-specific task agents only where beneficial, and verifies quality with criteria for the requested deliverable. Parent selects Skills by their *metadata*; the actual executor loads SKILL.md and follows it.

**Naming change:** v6.0 renames `$codex-hybrid-orchestrate` to **`$codex-universal-orchestrate`** and `orch_*` presets to **`cuo-*`**. These are new installed names; migrate v5 explicitly with backups. Existing unrelated Skills remain unchanged.

## Reliability improvements in v6.0

- **Adaptive Triage:** optional direct/planned/orchestrated decision; avoid unnecessary subagents.
- **Skill Eligibility:** inspect local Skill metadata, duplicates, and missing required Skills; confirm runtime/plugin Skills in the actual Codex session.
- **Verification Contract:** separate process, artifact and outcome checks with explicit evidence and approvals.
- **Execution Trace:** local, opt-in, allowlisted non-content records; no prompts, files, passwords or personal details.
- **Explicit name migration:** installed v5 users must retire the old `codex-hybrid-orchestrate` folder and `orch_*` presets via `--upgrade-v5`; v4 users use `--upgrade-v4`.
- CUO does not install or require lifecycle hooks; the Execution Trace remains opt-in.

## Install

Requires Python 3.11+. **All installer invocations are dry-run unless `--apply` is present.** Do not run scripts received from untrusted archives without inspecting them.

```bash
python3 scripts/install.py
python3 scripts/install.py --apply
```

If v5.0 is already installed, use `--upgrade-v5` explicitly. If v4 is installed, use `--upgrade-v4` explicitly (read the installation guide). If config exists, installer writes a merge fragment instead of overwriting it. In case of `AGENTS.override.md`, follow the installation guide.

## Validate configuration (offline)

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_plan.py examples/plans/cross-domain.json
python3 scripts/validate_plan.py examples/plans/research.json
python3 scripts/skills_inventory.py --project . --json
python3 scripts/triage_check.py examples/triage/cross-domain.json
python3 scripts/skill_eligibility.py examples/plans/research.json --project .
python3 scripts/verify_result.py examples/verification/ux-review.json
python3 scripts/trace_record.py examples/trace/event.json --out ./cuo-trace.jsonl
```

When migrating user-owned v5 JSON plans, use a dry-run first and request a **new** output path; existing plans are never overwritten:

```bash
python3 scripts/migrate_plan.py old-plan.json --out migrated-plan.json
python3 scripts/migrate_plan.py old-plan.json --out migrated-plan.json --apply
```

`validate_plan.py` checks DAG cycles, dependency references, conflict risk for concurrent writes, critical approval gates, model/preset consistency and required fields. It does **not** start agents or execute Skills. `skills_inventory.py` scans local filesystem Skills; it does not enumerate all plugin/built-in skills.

## Native usage

```text
В Codex: $codex-universal-orchestrate — разложи эту задачу по ожидаемым результатам,
используй уже имеющиеся Skills, создай независимых subagents только когда это выгодно,
назначь каждому нужную модель и Skill, проверь результаты и объедини их в main thread.
```

Use `/agent` to inspect children, `/skills` to confirm discovery, and `/model` to verify entitlement. Actual model/Skill use is not a deterministic promise from AGENTS.md.

## Routing defaults

- Main: `gpt-6.1-sol` medium; user can choose higher effort in UI/CLI.
- Unnamed child fallback: `gpt-6.1-sol` medium, so unknown subtask types are not silently assigned Luna.
- `cuo-scout`: Luna High (bounded exploration).
- `cuo-analyst`: Sol High (conceptual synthesis).
- `cuo-executor`: Sol Medium (scoped execution).
- `cuo-reviewer`: Sol High (independent quality assessment).
- `cuo-expert`: Astra Low (rare consequential decisions).
- Terra only optional A/B. Maximum subagent threads 5; normal target 0–2.

## Key safety requirements

- Installer does not trigger Codex sessions or touch project sources (except adding explicit project-scope instruction/config/skill files when asked).
- Children may inherit live parent permissions that supersede profile defaults. Confirm actual permission mode.
- Read-only agent presets are not a substitute for OS sandbox or external tool permissions.
- No automatic `codex exec`, Git worktree creation, merge, push or deployment. Launcher remains an **optional v4-compatible separate tool** with explicit user opt-in.
- Model entitlement varies; being signed in does not guarantee all preset models.
- Universal task manifest is NOT a native Codex API and doesn't enforce runtime behavior by itself.

## Migration from v5.0 (explicit)

```bash
python3 scripts/install.py --upgrade-v5
python3 scripts/install.py --upgrade-v5 --apply
```

This backs up & retires unchanged old `~/.agents/skills/codex-hybrid-orchestrate/` and `~/.codex/agents/orch_*.toml`, then installs the new paths/names. If old files were modified, the preflight blocks; review backups or use `--archive-modified-legacy` only when you explicitly accept retirement of those edited files. It does **not** rename unrelated Skills. Global `~/.codex/config.toml` is preserved, and `AGENTS.md` is updated only inside the marked block.
